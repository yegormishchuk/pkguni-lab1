## 1. Цель работы

Изучить цветовые модели RGB, XYZ, CIE LAB и CMYK и алгоритмы перехода между ними. Разработать интерактивное приложение, отображающее цвет одновременно в четырёх моделях с возможностью редактирования из любой из них.

---

## 2. Реализованные требования

- Все преобразования реализованы вручную, без сторонних библиотек.
- **Нет жёстко заданных матриц перехода.** Матрица RGB → XYZ вычисляется программно из цветностей основных цветов sRGB и белой точки. В интерфейсе выбирается стандарт освещения **D65 / D50 / E**, при смене матрицы и опорный белый для LAB пересчитываются на лету. Текущую матрицу можно увидеть в интерфейсе.
- **CMYK** с выбором алгоритма цветоделения: **GCR** или **UCR**. CMYK можно редактировать.
- **Выход за цветовой охват**: выбор стратегии **Clipping** или **Scaling**, с предупреждением.
- **Динамические градиенты на ползунках**: фон каждого ползунка показывает, какой цвет получится при его перемещении при текущих значениях остальных компонентов (во всех моделях).
- Архитектура **Model / View / ViewModel**.
- **Автоматические тесты** математики и ViewModel (25 тестов).
- Задание цвета ползунками, числовыми полями и палитрой; предпросмотр с HEX-кодом.

## 4. Ход работы

### 4.1 Структура проекта (MVVM)

```
index.html, style.css
js/
  model/colorMath.js            — Model: чистая математика, не знает об интерфейсе
  viewmodel/colorViewModel.js   — ViewModel: состояние, пересчёт, градиенты; без DOM
  view/colorView.js             — View: разметка, ползунки, события → вызовы ViewModel
  main.js                       — связывает View и ViewModel
tests/
  colorMath.test.js             — тесты Model
  colorViewModel.test.js        — тесты ViewModel
```

Поток данных: View получает ввод → вызывает команду ViewModel (`setComponent`, `setIlluminant`, `setGamutMode`, `setCmykMode`, `setHex`) → ViewModel вызывает функции Model и формирует состояние → View подписан на состояние и перерисовывается.

### 4.2 Построение матриц перехода

Исходные данные — только определения стандартов: цветности основных цветов sRGB `r(0.64, 0.33)`, `g(0.30, 0.60)`, `b(0.15, 0.06)` и цветности источников:

| Источник | x | y | XYZ белого |
|---|---|---|---|
| D65 | 0.3127 | 0.3290 | 0.95046, 1, 1.08906 |
| D50 | 0.3457 | 0.3585 | 0.96430, 1, 0.82510 |
| E | 1/3 | 1/3 | 1, 1, 1 |

1. Цветность в XYZ: `xy → (x/y, 1, (1−x−y)/y)`.
2. Матрица `P` — столбцы XYZ основных цветов; масштабы `S = P⁻¹ · W_D65`; `M_sRGB = P · diag(S)`. Для D65 получается стандартная матрица sRGB (0.4124, 0.3576, 0.1805 …).
3. sRGB определён для белого D65, поэтому для другого источника применяется хроматическая адаптация Брэдфорда:
   `M_adapt = B⁻¹ · diag(B·W_dst / B·W_src) · B`, итог `M = M_adapt · M_sRGB`.
4. Обратная матрица `M⁻¹` вычисляется через алгебраические дополнения.

При смене источника видимый цвет сохраняется, а его координаты XYZ и LAB пересчитываются.

### 4.3 RGB ↔ XYZ ↔ LAB

Гамма sRGB:

```
C_lin = C ≤ 0.04045 ? C / 12.92 : ((C + 0.055) / 1.055)^2.4
C     = C_lin ≤ 0.0031308 ? 12.92 · C_lin : 1.055 · C_lin^(1/2.4) − 0.055
```

LAB (CIE 1976), опорный белый `(Xn, Yn, Zn)` — белая точка выбранного источника, `ε = 216/24389`, `κ = 24389/27`:

```
f(t) = t > ε ? ∛t : (κ·t + 16) / 116
L = 116·f(Y/Yn) − 16,  a = 500·(f(X/Xn) − f(Y/Yn)),  b = 200·(f(Y/Yn) − f(Z/Zn))
```

Обратно: `fy = (L+16)/116`, `fx = fy + a/500`, `fz = fy − b/200`,
`xr = fx³ > ε ? fx³ : (116·fx − 16)/κ`, `yr = L > κε ? fy³ : L/κ`, аналогично `zr`.

### 4.4 RGB ↔ CMYK

`C = 1 − R/255`, `M = 1 − G/255`, `Y = 1 − B/255`, серая компонента `g = min(C, M, Y)`.

- **GCR (замена серой компоненты):** `K = g` — серая составляющая заменяется чёрным во всём диапазоне.
- **UCR (удаление подложечного цвета):** чёрный вводится только в глубоких тенях (порог `t = 0.5`):
  `K = g ≤ t ? 0 : g · (g − t) / (1 − t)` — в светлых тонах K = 0, к чёрному плавно растёт до полной замены.

Затем `C' = (C − K) / (1 − K)` (аналогично M, Y). Обратный переход одинаков для обоих алгоритмов:
`R = 255 · (1 − C') · (1 − K)`.

Пример: RGB(51, 51, 51) → GCR: (0, 0, 0, 80 %), UCR: (61.5, 61.5, 61.5, 48 %).

### 4.5 Выход за цветовой охват

После XYZ → линейный RGB проверяется, попадают ли гамма-кодированные значения в [0, 1] (с допуском в пол-кода, 0.5/255). Если нет — показывается предупреждение и применяется выбранная стратегия:

- **Clipping:** `v' = clamp(v, 0, 1)`.
- **Scaling:** в линейном пространстве диапазон `[lo, hi]`, где `lo = min(0, R, G, B)`, `hi = max(1, R, G, B)`, пропорционально сжимается в [0, 1]: `v' = (v − lo) / (hi − lo)`. Соотношения между компонентами сохраняются.

Пример: LAB(50, 100, −100) → Clipping: RGB(180, 0, 255); Scaling: RGB(156, 0, 255).

### 4.6 Динамические градиенты

ViewModel для каждого ползунка строит набор цветов: берёт текущие значения модели, перебирает значение этого компонента от минимума до максимума и переводит каждый вариант в RGB (для RGB и CMYK хватает 2 точек, так как зависимость линейная; для XYZ и LAB — 16 точек). View задаёт их как `linear-gradient` в фоне ползунка.

## 5. Вывод

Разработано веб-приложение для перевода цветов между моделями RGB, XYZ, LAB и CMYK с архитектурой MVVM. Матрицы перехода не заданы константами, а вычисляются из цветностей основных цветов и выбранного источника (D65, D50, E) с адаптацией Брэдфорда. Реализованы два алгоритма цветоделения CMYK (GCR, UCR), две стратегии обработки выхода за охват (Clipping, Scaling) и динамические градиенты на ползунках. Корректность математики подтверждена автоматическими тестами.
